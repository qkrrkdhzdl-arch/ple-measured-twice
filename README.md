# measured-twice

An agent harness for **Google - Agent Harness on Physical-Engineering's Last
Exam** (Kaggle, deadline 2027-01-05 23:59 UTC, $400,000 main track).

The name is the working rule of the trade: measure twice, cut once. Most points
lost on PLE are not lost to bad engineering — they are lost to a deliverable at
the wrong path, a value copied instead of recomputed, a unit slip, or a run that
stopped early. This harness spends its budget on making those impossible and
then on the engineering itself.

## What it does

```
task ─► intake ─► survey ─► plan ─► build ─► gate ─► verify ─► fix ─► close
        (free)   (cheap)         (most)   (free)   (fresh)          (free)
```

| Stage | Model | Purpose |
|---|---|---|
| intake | no | file map of the project folder; deliverable contract parsed from the task text (exact paths and formats) |
| survey | yes, read-only | what is in the folder, the governing documents, the method, the traps, how a reviewer would check it |
| plan | yes, read-only | a verifiable checklist per deliverable, biggest scoring item first |
| build | yes, all tools | engineering work with `bash`, file tools, and the task's MCP applications |
| gate | no | deterministic checks on the graded paths: missing/empty file, corrupt archive, IFC header, JSON, placeholders, final message |
| verify | yes, read-only | a fresh reviewer reopens every deliverable and recomputes the decisive numbers |
| fix | yes, all tools | gap-driven repairs, bounded by the clock |
| close | no | kills scratch processes, writes the final message with paths and results |

Design notes and the reasoning behind each choice are in
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md); the experiment plan that turns
those choices into the writeup's ablations is in
[`docs/EXPERIMENTS.md`](docs/EXPERIMENTS.md).

## Why it wins on score per cost

* **The contract is extracted before any model call.** Deliverable paths are in
  the task text; parsing them costs nothing and prevents the most common
  zero-score failure.
* **The deterministic gate runs before the reviewer.** A missing file is not a
  judgement call, so it is caught without spending a reviewer's tokens on it.
* **MCP tools are selected, not dumped.** A task's application catalog can hold
  hundreds of tools (~500 KB of JSON). Only tools matching the task text are
  registered, and `mcp_search` pulls in more on demand.
* **Long outputs are clipped in the middle, and the conversation is compacted**
  with a digest of earlier steps, so a 6-hour task does not pay for the same
  spreadsheet dump on every turn.
* **Every stage has a clock share**, so a slow solver cannot eat the time the
  verification step needs.

## Files

| File | Purpose |
|---|---|
| `serve.py` | stage orchestration, tool dispatch, final message |
| `engine.py` | model loop: effort, clipping, compaction, retries, usage reporting |
| `contract.py` | deliverable parsing, deterministic checks, inventory |
| `mcpbridge.py` | MCP catalog indexing, query-based tool selection, tool calls |
| `taskbridge.py` | the competition's serve protocol (Apache-2.0, from the PLE kit) |
| `prompts/` | survey, plan, worker, verifier prompts |
| `tests/` | protocol end-to-end test with a stub model, MCP bridge test |
| `experiments/` | ablation configs, scoreboard, figure generation |
| `artifacts/` | dev-set outputs, generated by `eval/run.py` (not yet present) |

## Run it

Local checks need the competition kit (`github.com/google-research/ple`) and
Docker:

```bash
uv run python -m kit check ../measured-twice
uv run python eval/run.py ../measured-twice --env-file local.env
```

Tests that need no Docker:

```bash
python tests/mock_run.py         # protocol end-to-end: stub model + mock evaluator
python tests/mock_run.py --mcp   # same, with a mock MCP app served to the task
python tests/test_mcp.py         # MCP discovery, query selection, tool calls
```
